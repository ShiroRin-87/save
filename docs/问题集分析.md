# 适合 SEVE 架构的问题集分析

## 一、SEVE 的价值定位

根据 8 题测试结论，SEVE 在简单事实题上无法超越 Vanilla RAG。其架构优势体现在：

- 搜索结果**存在矛盾**时 → 冲突检测 + 来源追溯
- 搜索结果**碎片化**时 → 知识表跨源拼接
- 搜索结果**有误导**时 → 信息缺口检测 → 防御性保守
- 需要**精确引用**时 → 声明→原文一对一验证

因此，问题集必须能创造"搜索结果本身就不可靠"的场景。

---

## 二、快变类问题（时效性强，多源矛盾高频）

### 2.1 FreshQA `fast-changing` 子集（已内置，直接筛选）

筛选 `requires_fresh = true` 的问题单独评估。FQ398（Passover 日期，chabad.org vs timeanddate.com 冲突）已验证此方向有效。

### 2.2 RealTimeQA

| 项目 | 值 |
|------|-----|
| 来源 | Liu et al., 2024 |
| 规模 | ~300 题/周 |
| 特点 | 每周更新的时事问题（新闻、体育、金融、娱乐） |
| 优势 | 答案变化周期短（天~周级），搜索结果混杂新旧信息 |

### 2.3 StreamingQA

| 项目 | 值 |
|------|-----|
| 来源 | Liska et al., 2022 |
| 规模 | ~3,000 题 |
| 特点 | 基于新闻流的时间序列问答，每题有多个时间点的正确答案 |
| 优势 | 天然适合验证"搜索结果同时包含过时和当前信息"时的表现 |

### 2.4 自建：实时数据题

搜索结果极易出现多源矛盾，模板如下：

> "2026年X月X日比特币的收盘价是多少？"
> "特斯拉 2026 Q1 的营收是多少？"
> "当前美联储基准利率是多少？"

不同来源（CoinMarketCap vs Binance vs 新闻报道）经常给出不同数字。

## 三、专业深度类（信息碎片化，需精准引用）

### 3.1 自建：Galgame/ACG 领域专业题（推荐优先）

AB2、SAGA、anemoi 三道自定义题已验证：搜索结果来自百度百科、萌娘百科、VNDB、2DFan、贴吧等，信息碎片化严重，snippet 往往不完整。

**题目模板：**

| 题型 | 示例 |
|------|------|
| 发售时间线 | "XX社在YYYY年发布了哪几部作品？" |
| 制作人员分工 | "XX在《YYYY》中负责了哪些部分的剧本？" |
| 品牌/会社关系 | "XX社是什么时候从YY社独立出来的？" |
| 画师/声优归属 | "XX画师在YYYY年参与了哪些作品的制作？" |
| 跨社比较 | "XX社和YY社在2024年各自发售了几部作品？" |
| 引擎/技术细节 | "《XX》使用的是哪个游戏引擎？" |

**筛选标准：**
- 搜素结果 ≥2 条（否则无冲突可能）
- 答案涉及多个独立事实点（原子化后可评估召回率）
- 避开过于知名、搜索结果高度一致的题目

### 3.2 NoCha

| 项目 | 值 |
|------|-----|
| 来源 | Roberts et al., 2024 |
| 规模 | 1,001 个声明 |
| 特点 | 针对 2024 年后新书的短篇事实验证，模型无法依赖训练记忆 |
| 优势 | 模型必须基于给定文本推理，专业且无法作弊 |

### 3.3 FACTOR

| 项目 | 值 |
|------|-----|
| 来源 | Muhlgay et al., 2024 |
| 特点 | Wikipedia 编辑历史中的争议性声明 |
| 优势 | 每条声明有明确的多源冲突历史，天然适合反向验证 |

### 3.4 医疗/药品信息

商业广告、科普文章、学术论文混在一起，信息质量参差不齐：

> "XX药物对孕妇的安全性分级是多少？"
> "2025年FDA批准的ADC药物有哪些？"

## 四、问题筛选标准

从任何数据集中筛选子集时，优先选满足以下条件的问题：

| 特征 | 对应 SEVE 模块 | 预期效果 |
|------|---------------|---------|
| 多源答案不一致 | 结构化抽取 → `[冲突]` 标注 | 冲突检测生效 |
| 搜索结果含噪音 | 抽取只取事实，滤噪音 | 生成质量高于直接 RAG |
| snippet 碎片化 | 知识表跨源拼接信息点 | 召回率不输 RAG |
| 需要精确引用 | 引用→原文一对一验证 | PARTIAL 判定有语义 |
| 有不可回答的陷阱题 | 信息缺口检测 | 拒答正确率提升 |
| 涉及精确数值/时间 | 反向验证 YES/PARTIAL 判断 | 引用精度可量化比较 |

## 五、实操路线

```
Phase 1（立即）: FreshQA fast-changing 子集分层分析
  → 验证 SEVE 在快变题上是否优于 baseline
  → 如果优于 baseline，这就是核心发现

Phase 2（同步推进）: 自建 50-100 道 Galgame/ACG 专业题
  → 深挖你的领域优势
  → 调优抽取 prompt 适配中文 niche 领域

Phase 3（备选）: 引入 RealTimeQA 或 NoCha 做跨领域泛化
  → 只在 Phase 1/2 有正结果后才做
```

---

## 六、注意事项

1. **不要引入英文基准后再调中文 prompt**——这是两个独立变量混在一起
2. **每个问题集需要独立的 search_cache**——不同时间搜同一问题返回可能不同
3. **先验证"SEVE 在什么条件下有效"，再跑全量评估**——避免 600 题全跑完才发现没有显著差异
4. **FreshQA 的 `fast-changing` 子集数量有限（~100 题）**——如果差异不够显著，需要自建题或 RealTimeQA 补充
